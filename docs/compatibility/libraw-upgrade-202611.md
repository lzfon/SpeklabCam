# RAW 解码升级：LibRaw Snapshot202611

日期：2026-11-15。升级前 Android 提交为 `77b38a2`，应用版本保持 `0.1.6`、versionCode `7`。

## 原因与依赖

用户提供的 Nikon Z5 II NEF 使用 HE★ 压缩。旧 LibRaw 0.22.2 将该文件分派给普通 `nikon_load_raw()`，解包与处理返回成功，却累计产生 17,918,099 次数据警告并输出彩条。问题在传感器数据解码阶段，胶片与相纸处理之前即可复现。

官方 2026 年 11 月 7 日发布的 [Snapshot202611 说明](https://www.libraw.org/news/libraw-202611-snapshot)加入 Nikon HE/HE★ 实际解码及 Z5 II 支持。稳定版 0.22.3 的对应函数仍为不支持的占位实现，所以本次使用固定快照，而不是仅修改机型白名单。

| 项目 | 固定值 |
| --- | --- |
| 版本 | `0.23.0-Snapshot202611` |
| 官方源码提交 | `a9a14b1970d188c25dade81f8326ff00a6e33649` |
| 源码压缩包 SHA-256 | `8dc5d15096c3fb15f90415a6915f152489ed7c57b3755e7dde7b1ba81e710895` |
| 配置事实源 | [`tools/libraw.lock.json`](../../tools/libraw.lock.json) |

运行 `python tools/setup_libraw.py` 准备源码。有代理时可加 `--proxy http://127.0.0.1:7890`；已有归档可使用 `--archive <path>`。脚本检查归档 SHA-256、路径和整个已解压目录，不覆盖被修改的依赖。CMake 额外核对关键头文件和 HE 实现摘要，缺失或错误时构建失败。Android 路径使用 `THEIA_LIBRAW_SOURCE`，与桌面引擎的旧 LibRaw 依赖独立；配置和头文件不混用。

本次仍不启用 OpenMP。选择 LibRaw 提供的 LGPL 2.1 许可选项；版权和原始双许可文本保存在 `app/src/main/assets/licenses/LibRaw-*`，官方固定源码由锁文件和下载脚本定位。未将相机原片打入安装包或提交。

## Android 适配边界

- 保留 AHD、相机／自定义白平衡、16 位线性 ProPhoto、关闭自动增亮、既有尺寸和输出编码设置。
- 保留胶片与相纸测量配置、shader、色彩处理、颗粒和光晕的原有计算及随机语义。
- 使用官方提供的 HE 分块虚函数接口，按原顺序调用三遍处理的 tile body，只增加当前解码线程上的取消检查；不替换公式，不引入额外并行任务。
- 遇到 Nikon HE 元数据与实际分派函数不匹配时停止解码，防止再次产生“成功的乱码”。转换后的 DNG 可保留 Nikon MakerNote，因此 DNG 不受此 NEF 分派检查误拦截。
- 导出缓存身份读取实际原生库的版本、固定源码提交及 Android 适配版本。旧结果不会与新解码结果混用；不删除图库、编辑或观景台数据库，也不清空用户项目。
- 相机内嵌 JPEG 仍仅用于原图显示参考和分析，不替代正式 RAW 显影输入。

## 验证方法

本轮证据存于本地 `.tmp/libraw-upgrade/`。旧版签名 Release、Release 原生库测试宿主、源码／资源摘要和原始失败记录均单独保留。测试宿主只在可测试 Debug 外壳中装入逐字节核对过的 Release 原生库；不能将其称为正式签名 APK 的全流程运行验收。

新增 opt-in instrumentation：

```text
raw-upgrade-baseline  记录旧版 RAW 像素与元数据
raw-upgrade           对照旧版逐位比较
raw-upgrade-he        HE★ 原片、独立像素参考、解码中取消、截断拒绝与实际导入导出
```

相机素材位于目标应用 external files 的 `raw-upgrade/`，不进入 assets。基线包含六种 12／14 位 Nikon Z6 II NEF、Bayer DNG、小米 DNG、Sony ILCE-7M3 压缩 ARW 和 Canon EOS R CR3；公开补充素材有 CC0 来源和 SHA-256 记录。HE★ 单独使用用户提供的 Z5 II 原片。像素对照分别覆盖默认和自定义白平衡、2048 长边预览、相机矩阵、相机白平衡元数据与 320 长边正式解码采样。

效果比较使用全部胶片与相纸的兼容组合，完整 U16 数据逐字节比较；另外核对真实 24MP RAW 的完整 TIFF 摘要。确定性基线关闭随机颗粒与眩光，其开关、默认路径和参数另由既有功能回归检查，不能把随机噪声逐次完全相同当作要求。

性能使用相同模拟器、Release 原生库和相同输入尺寸，保留预热、逐次计时、完整像素摘要、首导与缓存导出。交错安装旧／新版，核对调参、胶片与相纸、RAW 白平衡和解码性能；编译不与正式性能采样同时执行。不得通过降分辨率、位深或编码质量换取速度。

## 最终回归与性能结果

首个候选构建完成 36 组、208 条相关回归，全部通过，覆盖原图颜色、权限、取消、胶片效果、调色、预设、批量与单张导出、图库和观景台存储。随后只在生产代码增加“转换 DNG 保留 Nikon MakerNote”的豁免守卫，最终构建又完成 16 组、19 条 RAW／HE、原图、素材、全尺寸导出、缓存和存储复测，全部通过；32 组素材输出及三份完整 TIFF 摘要再次核对相同。

性能矩阵覆盖 52 项后期、89 项原生参数（包括全部胶片和相纸）、3 项 RAW 白平衡及一次镜头校正。旧、新、旧、新四轮使用相同尺寸和 Release 原生库；每轮各项均先预热后计时。合并新旧各六次采样，按每项中位数再求和：

| 场景 | 新版／旧版耗时比 | 说明 |
| --- | --- | --- |
| 52 项后期 | 1.023 | 约 +2.3%，52 项像素摘要均相同 |
| 89 项胶片／相纸等原生参数 | 1.009 | 约 +0.9%，单项有波动 |
| 3 项 RAW 白平衡 | 0.956 | 约 −4.4%，不含一次镜头校正样本 |

最后相邻的一对旧、新矩阵，52 项后期中位数之和为 3566.53 → 3551.13 ms，89 项原生为 17423.61 → 16980.40 ms。它们是多项测量之和，**不是单次操作延迟或 FPS**。本轮没有测出持续的整体速度回退，也不能据此保证每个参数、每台手机都完全相同。

对白点和品红 HSL 首轮异常另做旧、新、新、旧集中复测：每项先预热 5 次，再测量 15 帧，新旧各 30 次，完整像素摘要保持。白点为 30.90 → 32.69 ms，品红 HSL 色相为 96.29 → 94.37 ms，原来的约 110／216 ms 高值未持续复现；对比度为 33.00 → 36.92 ms，中性为 16.04 → 16.40 ms。保留这些毫秒级差异，没有宣称所有单项“零退化”。此补测只增加测试代码，没有重新修改正式 APK。

针对首轮 Sony 与 DNG 偏高的读数，另用新旧实际 Release LibRaw 静态库、同一 C++ 程序隔离解码，按旧、新、新、旧执行。每次先预热一轮，再测五轮，以下为新旧各十次采样中位数：

| RAW | 旧版 ms | 新版 ms | 旧／新最大 RSS KiB |
| --- | --- | --- | --- |
| Sony ILCE-7M3 压缩 ARW | 260.42 | 258.11 | 135672／135752 |

最终 Release 为 56,330,265 字节，SHA-256 `43188f3df78d8fa20a09c7db172c206cfe04a198c7c9db6027b7c2c5ad82c818`。原更新证书、V1／V2／V3、两种 ABI、六份原生库的至少 16 KiB ELF LOAD 对齐和 APK 16 KiB 对齐通过。实际测试后拉回的宿主 APK 与准备的 Release-native 测试包逐字节相同。详细原始记录在 `.tmp/libraw-upgrade/verification.json` 及各批次目录，交付包附带同类验证清单。

## 验收边界

运行证据来自 API 37 x86_64 模拟器，ARM64 完成编译不等于 ARM 真机已验收。HE 解码有额外工作内存；PSS 阶段快照不等于全程峰值。真机 GPU 驱动、温控、低内存长时间连续操作、更多 HE／HE★ 机型和压缩变体仍需实测。

没有 S24 用户失败原片，不能把本次 Nikon 修复说成已验证解决三星 Expert RAW 的所有 DNG 变体。F03 的 50MP／IIR 等原未完成项及其他工作包的剩余范围继续保留。

已经保存在观景台项目中的历史预览不会被静默改写。若先前保存过 HE 乱码预览，需要重新显影并显式更新项目；项目布局和编辑记录不会因本次升级被清空。
