# RAW 窗口化导出与存储缓存专项

日期：2026-11-15。范围：小米 17 Pro 在前一修复包中，CineStill 800T + Vision 2383 原尺寸仍花屏；处理 RAW 后系统“应用存储和缓存”持续增大。原片仍为 6064×4040 的 `DSC_5099.NEF`，SHA-256 为 `cafd8050d216fd08923eb972221c2011c2a4d39cda33efb6b0ed39e2a77ede3b`。

**提交前性能复核和最终 APK 以 [代码复核报告](../engineering/export-review-2026-11-15.md) 为准；下列包摘要和计数是复核前阶段证据。**

**本轮最终包完成模拟器正常策略和受限策略的验证；未连接小米 17 Pro，真机验收仍待完成。** 之前只补齐安全调度变体，不能证明真实设备的大图绑定问题已经解决。本文件替代前两轮针对该问题的当前结论，历史证据保留。

## 确认的问题

### 工作量分段不等于绑定范围分段

上一轮虽然把一次 dispatch 限制到较少 invocation，但 descriptor 仍可绑定整张图。24.5MP 的 RGB32 中间平面约 280 MiB，已经大于一些设备的单次 storage-buffer 绑定能力。

本轮将模拟器后端限制为 128 MiB，并禁止 CPU 设备启动探针放宽该限制。初轮真实 CineStill 用例明确失败：`spk_reduce_max: buffer exceeds maxStorageBufferRange`。这证实旧路径尚有完整图像绑定缺口，不能将成功的宽松模拟器结果当作手机通过。修复前证据保留于 `.tmp/libraw-upgrade/windowed-strict/`。

参考对象是 [SAINTTaiYi/SpektraLab-Android](https://github.com/SAINTTaiYi/SpektraLab-Android)，读取 commit `b17f6d2bdcd8024bb62abf212d10819115ca2d87` 的调度补丁及分带文档。本轮采用其明确 offset/range、区分绝对位置和局部地址、核对成片的思路；没有替换光谱数据或整包覆盖本项目引擎。

### 磁盘成片缓存与应用运行内存不是同一件事

用户确认问题发生在系统“应用存储和缓存”，不是 RAM 读数。一份 6064×4040 RGBA16 成片仅像素就需要 195,988,480 字节，约 187 MiB；它自然大于约 30 MB 的压缩 NEF。

旧成片缓存上限为 512 MiB；缓存身份还包含安装时间和 APK 内容，覆盖安装后旧条目已经无法命中，却可能继续留到容量淘汰。另有进程异常退出遗留的命名暂存文件、分享预览临时图需要定向回收。编辑数据库、项目和原片不能按缓存处理。

## 实现与模块职责

| 模块 | 本轮职责 |
| --- | --- |
| `cpp/windows/window_plan.hpp` | 明确每个 binding 的元素步长和 kernel 类型；不从缓冲池分配大小猜测像素布局。这里的 windows 指绑定窗口。 |
| `WindowedDispatch.cpp.in` | Vulkan 1D 提交、每次重新绑定 offset/range、设备对齐、窗口内地址原点、工作组尾线程保护、FIR halo、缩放及几何源范围。 |
| `WindowedIir.cpp.in`、`spk_window_copy.comp` | 按列打包/还原，单列仍按原顺序完成全部正向和反向递推；不把滤镜切成相互独立的小图。 |
| `WindowedReduction.cpp.in` | 最大值归约按网格对齐的有界切片执行，保留原 kernel 的组分配，再合并有限最大值；不平均或量化像素。 |
| `tools/windowed_shaders.py` | 展开 GLSL，并将存储地址改为相对各 binding 的原点；绝对索引继续用于颗粒种子和几何。原始 shader 保留。 |
| `RenderAppearance`、`RenderHostService` | 原尺寸 RAW 用同一冻结原生参数计算小尺寸结构参考；保存前检测明显大块黑带、结构丢失或无效 alpha。参考不会替代导出像素。 |
| `RenderDiskCache`、`ExportRenderCache` | 256 MiB 成片预算、7 天未使用淘汰，租约保护及原有完整性检查。 |
| `CacheGeneration` | 按安装代际回收不能命中的旧成片缓存；同一安装内保留有效加速缓存；原子且有界读取标记。 |
| `CacheMaintenance`、`TheiaApplication` | 仅主进程后台 IO 清理超过 24 小时的已知暂存文件和分享临时图，不遍历删除用户资料。 |

工作窗口默认最多 64 MiB，也受设备硬上限限制。每个 descriptor 偏移满足设备对齐，push constant 为 72 字节。窗口尾线程在访问任何 binding 前返回，不能写进下一块。缓冲池另外记录请求的逻辑 `used` 长度，不能将较大分配容量当成图像长度。

本轮编译 47 份窗口寻址变体。**这不表示所有跨网格算子的源图都完成了分窗**：部分片边/proof/双图分支保留合法的整幅读取合同，只在真实设备上限允许时执行，不能因较小的工作窗口政策额外禁用原来合法的功能。硬上限不足时明确失败，不静默缩小。更完整的跨网格分解仍是 F03 剩余项。

新增原生代码按提交、IIR 和归约分文件，经过固定版本 clang-format。CMake 显式跟踪模板依赖，避免只改模板却继续使用旧生成源。共享桌面引擎 checkout 保持不动。

### 成片保护的边界

原尺寸 RAW 的结构参考长边为 640，仍使用相同材料、原生参数、色彩空间和随机身份。完整输出继续独立以原尺寸显影。仅保存少量亮度签名，既不把预览放大，也不改变最终像素。

这是保守的灾难性结果检查：结构明确的参考中出现连续大块缺失、明显结构塌缩，或采样 alpha 无效时停止保存；平坦参考不作为可靠结构判断。它不是精确色差门限，不保证识别所有可能的花屏，不自动反复重试。该步骤增加首次原尺寸 RAW 的参考计算开销；命中已验证成片缓存时无需重新计算。

### 存储策略的边界

- 原片、编辑、图库项目、数据库和工作台均不参与删除。
- 成片仍是原 RGBA16 数据；容量优化没有将缓存改成有损 JPEG，也没有降低正式输出位深或质量值。
- 超过 256 MiB 的单帧仍可按原尺寸导出，只是不长期保留该加速缓存，因此此类照片重复导出需要重新显影。
- 7 天期限按最近使用时间计算；租约中的条目不会强制删除。
- 暂存清理只认已知文件名、直属路径和过期时间；近期分享文件、未知子文件、原片及编辑资料保留。
- 256 MiB 是成片缓存预算，不是整个应用大小上限。APK、解压后的引擎资源、原有受限观景台预览及用户项目仍需各自空间。

## 最终包验证

同一生产构建的 Release 原生库和资源装入可审计宿主，运行于 API 37 x86_64 模拟器。

| 验证 | 结果 |
| --- | --- |
| 默认策略 | 16 组、25 条功能记录全部通过。 |
| 128 MiB 硬绑定上限 + 8 MiB 工作窗口 | 8 组、8 条全部通过；包含冷缓存真实 RAW、独立 PC 捕获、归约、IIR、几何和片边日期。 |
| 覆盖安装后的回收 | 另 1 条通过；真实成片缓存目录从 197,596 KiB 降至 24 KiB，回收约 193 MiB 不可复用缓存。 |
| 实际原尺寸 | CineStill JPEG/PNG 均为 6064×4040；50MP JPEG、DNG 同批导出均为 6144×8192。 |
| 完整 PNG 像素 | 与窗口化前正确成片比较 73,495,680 个通道，最大差异 0；像素摘要保持 `9b93d347330cd72f46bb034981c13908f81ac5e33d2de27f47e283ffb1abe456`。 |
| 独立 PC 参考 | sRGB、ProPhoto RGB 各 73,495,680 个 U16 RGB 通道，最大差异均 1；均值分别 0.00217145 / 0.00131406。随机效果关闭以得到确定性参考，不代表任意后期完全相同。 |
| 完整 TIFF16 | 受限原生流程摘要仍为 `0fb5bfb67c269e4daae37d888971d8d7cf4fab9aabd9b0dfd316a3f41ca56ff0`；真实 CineStill 首次/缓存保持 `13ecf2f7c248b4066b6dc37b1728aca5f2e73e894758bee2f345208759cf1a3c`。 |
| 原生计数 | 受限轮 29 条渲染记录，列打包和窗口归约实际执行；最大记录绑定约 27 MiB，来自仍有整幅读取的片边分支，在 128 MiB 硬上限内。工作窗口 8 MiB 不等于这些兼容分支的全部只读绑定也为 8 MiB。 |
| 缓存安全 | 过期、旧安装代际、旧大预算和损坏标记通过；同安装有效缓存、租约像素、近期文件及原片/编辑/数据库保留。 |
| 其他回归 | 25 胶片/9 相纸的 32 组参考、随机光晕、编码/元数据、取消、发布恢复、进程 host、项目恢复和观景台外观通过。另 6 项 Python 测试通过。 |

以上共 34 条执行记录，去重 28 用例；另有独立逐通道比较与 Python 测试，不重复计入用例数。默认 64 MiB 策略该模拟器单次 CineStill TIFF 审计中，首次约 9.33 秒，缓存约 0.92 秒；这是单个样本而非手机速度承诺。8 MiB 诊断策略会增加提交和拷贝，不能拿该耗时当默认性能。

原始证据：`.tmp/libraw-upgrade/windowed-normal/`、`windowed-final-strict/`、`windowed-upgrade/`。汇总、签名、原生计数、PNG 比较与 PC 比较在 `.tmp/windowed-export/`。476 项生产构建输入冻结，97 份原引擎资源、170 项共享引擎输入与 LibRaw 源保持；测试宿主与 Release 的六份 SO 和引擎资源相同，六份 ELF LOAD 对齐至少 16 KiB。
