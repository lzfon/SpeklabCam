# 原尺寸导出代码与性能复核

日期：2026-11-15。提交基线：`791c3f0`。审查范围为本次尚未提交的导出执行架构、RAW 并行、窗口寻址、逐行编码、进程交接和缓存维护；不代表全部开发计划已验收。

## 代码审查结论

已核对冻结请求和随机身份、单张与批量共用链路、Binder 文件描述符所有权、晚到回包清理、取消与发布边界、设备释放确认、缓存租约及定向清理。当前验证范围内未发现阻止合入的功能错误。分包与共享层依赖检查通过；共享桌面引擎、LibRaw 源和全部原引擎资源保持。

导出职责分布在 `core/model`、`data/export`、`data/cache`、`engine/host`，GPU 窗口实现分为调度、IIR 和归约模板，避免继续扩大编辑器的导出实现。新模板由 CMake 跟踪输入变化。当前模板适配仍依赖上游源锚点，锚点变化会使构建明确失败，需要同步复核，不能视为与任意上游版本自动兼容。

预览继续走原正常调度；窗口合同只用于一次性导出。资源和输出均有确定的关闭路径，匿名暂存文件在写入照片字节前取消目录链接；缓存维护保留原片、编辑、数据库和项目。

## 本次补充优化

第一轮交错测试发现冷导出存在明显开销：窗口化版本 CineStill TIFF 首次中位数 9972 ms，对照 8253 ms。不能将这批改动描述为“性能没有受到影响”。

复核后将完整 IIR 列的打包和还原改为多区域 `vkCmdCopyBuffer`：每个最多 32 MiB 的临时平面用一次批量字节传输，减少逐带 gather/scatter 着色器提交和元数据上传。保留取消检查、合法长度检查、传输前后内存依赖，以及原始完整双向递推。没有改变浮点运算、颗粒位置、尺寸、位深、JPEG 质量值或关闭效果。

## 最终构建交错耗时

API 37 x86_64 模拟器，同一份 `DSC_5099.NEF`，输出 6064×4040。对照为本地 `full-size-fixed/host.apk`，最终版为 `windowed-review/host.apk`，**不是历史发布版与真机的速度比较**。每版三轮，顺序为旧、新、新、旧、旧、新，四项诊断属性均为 0。

原生流程含解码、镜头校正、打开、显影和 TIFF16 编码；实际应用流程另外含源快照、进程通信、原尺寸 RAW 结构参考、缓存和发布。两项基准关闭颗粒和眩光以核对完整确定性摘要；启用效果另由真实应用和完整像素回归覆盖。实际应用计时还包括测试完成轮询和输出摘要读取，不是纯编码耗时。
