# Windows 风格导出执行：首轮落地与验收

最新跟进：[RAW 窗口化导出与存储缓存专项](../compatibility/raw-export-windowed-v2-2026-11-15.md)。后续真机反馈说明“只分 dispatch”仍不充分；现补充 descriptor 窗口、IIR 列打包、分窗归约、生产成片保护和缓存代际回收。下文保留首轮历史数字，不作为最新包身份或真机通过声明。

日期：2026-11-15。开发基线：`791c3f0`。方案：[Android 与 Windows 一致的导出执行方案](windows-export-parity-plan.md)。

后续修订：小米 17 Pro 的真实原尺寸异常揭示了此前安全着色器覆盖不完整的问题。原 35 份安全变体实际漏掉 11 个共享/内联索引内核，现已补齐为 46 份并禁止缺失时静默回退。下文的构建摘要和计时属于首轮历史证据，不是本次修复包身份；最新验证、独立 PC 对照、新包和 ARM 剩余项见 [RAW 原尺寸异常专项](../compatibility/raw-full-size-corruption-2026-11-15.md)。

本轮实现单张、批量照片导出的请求冻结、独立渲染进程、有界 CPU 并行、随机实现身份、成片缓存、有界 GPU 提交和低驻留编码。**这不是 E1–E6 全部完成的声明**，也不把模拟器结果当作 ARM 手机验收。现有编辑、材料测量文件和输出质量设置保持。

## 实际模块与执行顺序

| 模块 | 本轮职责 |
| --- | --- |
| `core/model/ExportFrameRequest` | 版本化请求；源 SHA-256、材料/编辑快照、解码和输出选项、引擎身份及已解析随机身份。 |
| `data/export/PhotoExportPipeline` | 单张/批量共用的准备、缓存、渲染、编码与提交路径。 |
| `data/export/ExportCoordinator`、`ExportJobStore` | 串行协调、私有原子事务日志、阶段和发布凭据、下一次接受任务前恢复未完成凭据。 |
| `engine/host/RenderHostClient`、`RenderHostService` | `:render` 独立进程；异步 Messenger 控制、小消息及只读文件描述符；进度/取消旁路。 |
| `engine/host/RenderHostLease` | 用户点击时建立前台服务租约，覆盖准备、批次内所有照片和编码；任务结束解除绑定。 |
| `engine/host/NativeSessionOwner` | 单个原生执行队列；批次内短暂复用空设备；恢复预览前等待设备释放确认。 |
| `data/export/EphemeralExportFile`、`ExportSourceSnapshot` | 原文件字节直接暂存；写照片前取消目录链接，依文件描述符持有，关闭或进程结束即回收；不转换为 JPEG 原片代理。 |
| `data/export/PngRowWriter`、`JpegRowWriter` | PNG 逐行无损写出；API 30+ JPEG 用相同系统编码器读取文件后备 RGBA8；TIFF 保持已有逐行 16 位写出。 |

导出冻结编辑和选项，复制并校验原片字节，读取同一份元数据；命中已验证的成片缓存可直接编码。未命中时先释放编辑端计算设备，再在渲染进程中解码、镜头校正、显影和扫描。U16 成片通过只读描述符按行访问，调色和编码后才提交到相册。本地/MediaStore 原片在提交前再次核对；改变的原片拒绝发布。云端流只抓取一次，以持有的不可变副本为本次源身份。

恢复编辑前显式等待 `DEVICE_RELEASED`。批次内可复用的空闲 Vulkan 设备不能与重新创建的预览计算设备长期并存；清退超时则受控结束该 worker。空闲延迟回收是兜底，不代替这个交接确认。

## 资源与失败合同

- 原片、float 数组和整张 Bitmap 不经过 Binder。请求 UTF-8 上限 128 KiB，响应只包含作业标识、阶段、尺寸、错误类别和描述符。
- 源暂存容量上限 1 GiB，并保留至少 64 MiB 可用空间；成片暂存与编码也先核对空间。不足时明确失败，不改变尺寸、位深或效果。
- 临时文件在写照片前取消目录链接。强制结束恰好落在分配与取消链接之间，最多留下零字节分配文件；这不是原片副本。验收检查当前描述符链接状态及是否存在含照片字节的命名残留。
- 沿用已有 512 MiB 成片缓存和租约、校验及淘汰规则。缓存是可删除的衍生 U16 成片，不是原片/编辑记录。尚未开放独立源/负片/扫描阶段缓存。
- RAW AHD 与镜头逐像素算术不变；静态 OpenMP 最多 4 个线程，关闭嵌套活动层并恢复调用线程的原有设置。LibRaw 工作线程不跨线程使用 `JNIEnv`，仅观察取消锁存；Java 回调留在拥有者线程。
- 捕获设备丢失后锁存失效状态，禁止旧设备继续渲染、轮询或取消。显式重新打开源才能重建新设备代次；不会自动无限重试或降低质量。
- worker 死亡、取消和错误不发布半张图片。发布记录的 pending URI 在恢复时清理，已完成提交保留；不是按同名文件猜测成功。
- 前台服务按 API 选择 `mediaProcessing` / `dataSync`。准备和批量期间持续绑定，支持返回桌面和息屏；CPU 租约有超时并在解绑、销毁、系统超时时释放。主进程死亡后安全结束任务，不承诺自动续跑未完成导出。
- JPEG 质量值不变，仍然属于有损格式。PNG 保持原有 8 位输出，TIFF 保持 16 位；没有用降低位深或关闭颗粒/光晕取得提速。

## GPU 提交与随机身份

35 个具有明确一维全局索引合同的着色器生成独立 `.bounded.spv` 变体，原始着色器保留。有界版本以 Vulkan 1.0 的 4 字节 push constant 传入全局基址；普通点运算每次最多 1,048,576 个 invocation，IIR 每次最多 2,048 条线/通道 invocation。每次提交保留必要同步，并在提交之间检查取消。

IIR 的一条线仍运行完整的双向双浮点递推，未把线段独立模糊后拼接。其他手写索引/探针内核不套用未经验证的切分。**这降低单次提交工作量，不代表整图显存峰值已经降低。**

请求明确携带 film/print seed 及随机合同版本。兼容值来自现有全新管线 SplitMix64 的首两次取值；胶片颗粒关闭时，打印端沿用第一次取值。原生作用域只绑定本次导出，不注入未经引擎支持的 wire 字段，不关闭随机效果。种子纳入缓存身份；未解析身份的旧调用者仍保守绕过随机缓存。日期后背和片边暂不因此开放缓存。

## 验证方法与证据

生产代码和依赖使用 `tools/record_development_baseline.py` 冻结。共享 Windows 引擎 checkout 未修改；Android 通过本仓库构建适配器生成扩展源。实际 APK 的签名、ABI、依赖、着色器和素材摘要单独核对。

新增审计：

- `windows-export-recovery`：三种设备丢失消息、非丢失错误不误判、失败句柄拒绝、取消安全、显式重建与像素一致。它是故障状态注入，不是真机驱动复位复现。
- `render-host`：不同 PID、完整 U16/任意行读取、原片匿名描述符、请求冻结、worker 强制结束/重启/取消/版本拒绝、息屏后台连续帧及设备释放/重建确认。
- `bounded-export`：8193×281 中性、颗粒眩光、仅眩光、CineStill 物理光晕；原整次调度、有界调度、显式随机身份的完整 U16 对照。
- `export-lifecycle`：pending 记录恢复、已提交文件保留、编码中源文件改变后拒绝提交。
- `export-encoding`：全部 65,536 级量化样本、PNG 逐行像素和 EXIF/GPS、JPEG 质量 50/80/95/100 与原 Bitmap 路径解码像素一致、写失败清理、16 位 TIFF 和提交取消。

另沿用 RAW 老样本/HE★、源访问/取消、单张/批量三格式、真实相机全尺寸、编辑/项目恢复、观景台外观、CineStill、材料、曲线、色轮和混合等回归。测试报告、交错计时和最终完成数量在本文件的验收结果段落核对。

### 交错性能结果与边界

样本是用户 `DSC_5099.NEF`，相机元数据为 Nikon Z6_3，输出 6064×4040。设备中的 `perf-z6ii.NEF` 只是历史测试别名；原始字节 SHA-256 为 `cafd8050d216fd08923eb972221c2011c2a4d39cda33efb6b0ed39e2a77ede3b`。before 使用本轮 E1 恢复绿版宿主，after 使用最终宿主；它不是完整历史发布版与新 UI 点击耗时的比较。

基准直接执行 RAW 解码、镜头校正、上传、原生显影和 TIFF16 编码，每组独立安装三次，不使用成片缓存。两端都关闭颗粒和眩光以获得可核对的确定性基准；正式功能仍保留这些效果，并由上述像素专项验证。计时不包含应用的源快照、IPC、完整后期和相册发布。

各阶段和总耗时分别取中位数，阶段中位数不应相加当作总中位数。小样本模拟器测量只能说明本次环境的结果；编码范围重叠，不据此声称编码算法退化或手机同比提速。GPU 有界提交在该环境出现明显渲染开销，未关闭安全边界来追求更短单次时间，后续需要 ARM 驱动实测和调度优化。

六份 TIFF 都为 146,991,552 字节，完整 SHA-256 为 `0fb5bfb67c269e4daae37d888971d8d7cf4fab9aabd9b0dfd316a3f41ca56ff0`。新旧临时池 frame high-water 均为 1,175,931,252 字节，约 1121.46 MiB；这既不是设备总峰值，也不能证明整图 GPU 内存问题已解决。

实际应用的三格式审计包含启动、导入、预览、导出及可能的缓存复用；50MP 批次审计还包含独立 RAW 尺寸参考。因此不把这些用例的总墙钟时间作为单张冷导出速度。

### 构建与最终一致性

最终 Release 保持 `0.1.6` / code `7`，文件为 `app/build/outputs/apk/release/app-release.apk`，58,111,085 字节，SHA-256 为 `3292f557c98bfa34fb555d6f35a9c770d6d12db1622b5dd21cf265c72ef27408`。原更新证书的 V1/V2/V3 签名通过，双 ABI 的全部六份 SO LOAD 对齐至少 16 KiB；没有动态 `libomp.so` 依赖，也没有 API 30 `AndroidBitmap_compress` 的必需导入。

35 份有界着色器存在；102 份原资源、170 份共享引擎输入及独立 LibRaw 源保持。最终宿主与 Release 的六份原生库逐字节相同；404 项生产构建输入在收尾再次对照冻结清单，无漂移。诊断属性 `debug.theia.export_timings`、`debug.theia.export_fir_bands` 均为 `0`。构建、签名及汇总证据分别为 `.tmp/windows-export/build-verification.json`、`signatures.json`、`verification.json`。

本轮未提交、推送或发布。进度核对保留全部 20 个工作包及其剩余项，F03/F16 仍进行中；50MP 模拟器通过不等于真机显存、热稳定性或任意超大照片均已验收。
