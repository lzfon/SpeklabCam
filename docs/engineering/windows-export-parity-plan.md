# Android 与 Windows 一致的导出执行方案

日期：2026-11-15。基线：`791c3f0`。

实施更新：首轮代码及逐批验收范围见 [Windows 风格导出执行](windows-export-execution.md)。本文第 2 节的“当前实现”和诊断数字描述开发基线，不代表修改后的最终计时；E1–E6 尚未全部关闭。

本文件是实施方案，不代表下列模块已开发或真机验收。对应既有 F03 渲染与大图、F16 导出任务、F17 后期与输出一致性；不改动已保存的原片、项目、编辑参数或已有工作包状态。

## 1. 目标与验收含义

统一 Windows 的成片语义、阶段复用、失败行为和输出完整性，Android 按设备能力采用有界资源执行。不能承诺手机与独显 PC 相同耗时。

- 一次导出只读取一份不可变请求，处理中修改界面不能改变在途文件。
- 相同原片、解码设置、材料、参数、种子、输出尺寸与色彩意图使用相同计算规则。
- 全尺寸保持原始输出尺寸，不通过降低位深、简化 RAW 显影、关闭颗粒/光晕来提速。
- JPEG 本身仍是有损格式；所谓画质保持是保留用户选择的格式与质量，不声称 JPEG100 无损。
- Windows `export_frame` 是本轮目标，不回退到遗漏 Post-Dev 的旧 `export_image`/`write_image` 链路。
- 缓存有效就复用，失效只重算所属阶段；缓存清理不影响原片和编辑记录。
- 取消、进程退出和 GPU 失败后不发布半张图片，不静默降低质量或无限重试。

## 2. 已核对的差异

| 方面 | Windows 实现 | Android 当前实现 | 目标 |
| --- | --- | --- | --- |
| 所有者 | 独立 `spektralab-host` 管理会话 | 界面进程内 JNI 引擎，导出逻辑集中在 ViewModel | 独立受控渲染进程，统一会话所有者 |
| 缓存 | 复用有效负片/成片，必要时精确 suspend/resume | 有确定性磁盘缓存；颗粒、眩光、片边等绕过 | 可保存同一次随机实现的阶段缓存 |
| RAW | 有界 OpenMP 线程作用域 | LibRaw 构建显式关闭 OpenMP | ABI/运行库/像素验证后的受控并行 |
| 镜头校正 | 校准匹配和有界并行 | 自有串行全图处理 | 保持数学和采样结果的有界行并行 |
| 大图 | 资源回收、传输分块及缓存暂存 | 已做一次性生命周期与局部 FIR 试验，整图峰值仍高 | 包含全局统计、FIR、IIR 的完整资源规划 |
| 后期与输出 | 完整快照驱动 `export_frame` | 自有后期与编码，工作空间存在区别 | 新旧版本分离，独立核对完整输出表面 |
| 错误 | host 与窗口分离 | GPU 丢失后仍可能用旧引擎恢复预览 | 丢失状态锁存、清退设备、受控重建与重新绑定 |

当前诊断来自 API37 x86_64 模拟器，不能当作小米/OPPO 真机结果。同一 NEF 的一次默认全尺寸 JPEG 导出记录：RAW 3830 ms、镜头校正 4620 ms、输入 827 ms、渲染 1263 ms、编码发布 659 ms；合计 11199 ms。GPU 临时池高水位 1175931252 字节，不是进程或设备总峰值。Windows 保存的该照片没有开启镜头校正，因此这些数据不构成同工作量跨设备速度比。

用户反馈的 `VkResult -4` 属于设备丢失；其具体触发原因尚未在真机复现。独立进程、缓存或并行本身都不能证明 GPU 故障已经消失。

## 3. 目标结构

以下为最初的目标蓝图；已实现和仍缺的边界以实施更新为准：

```text
界面 / EditorViewModel
  └─ ExportCoordinator：提交、观察、取消
       ├─ ExportJobStore：请求、状态、发布凭据
       └─ RenderHostClient：异步 IPC、连接代次、故障通知
            ⇄ 小消息 + 文件描述符
          RenderHostService（:render）
            └─ NativeSessionOwner：单一重计算队列
                 ├─ RAW / 镜头校正
                 ├─ SourceCache / NegativeCache / PrintCache
                 ├─ Vulkan 预算、等价分段、设备状态
                 └─ Post-Dev → 输出几何 → 色彩转换 → 编码
       └─ ExportPublisher：校验完成文件后发布到相册
```

建议沿用现有 `core/model`、`data/export`、`engine` 和应用 Service 边界，不把更多引擎、IPC 或数据库代码塞进编辑页面。

预览与导出应最终共用渲染进程内的会话所有者。迁移期间如果保留两个引擎，导出前必须暂停并释放/暂存编辑端的 GPU 图面；不能让两套整图缓存同时驻留。界面可保留已显示的 Bitmap，后续恢复引擎按需执行。

Service 必须显式声明独立 `android:process`；仅创建 Service 或协程不会获得进程隔离。照片处理适配 foreground `mediaProcessing` 类型及对应权限、超时和停止规则。前台服务提供可见任务生命周期，不是速度优化，也不是永不被杀的保证。

IPC 仅发送请求描述、任务 ID、进度、结果凭据和文件描述符。原片、float 数组及整张 Bitmap 不经 Binder 消息复制。每个描述符定义唯一生命周期和关闭责任；复制出的描述符可能共享文件位置，不允许界面与 worker 无约束并发 seek/read。

## 4. 一次导出的完整请求

扩展现有 `EditSnapshot`、`ExportOptions`，建议形成版本化 `ExportFrameRequest`：

- `jobId`、请求 schema、渲染器代次与取消令牌。
- 原片资产/变体、源版本凭据、完整摘要或已验证的不可变源快照。
- 解码器实际身份、RAW 模式、白平衡、镜头开关、具体校准数据版本。
- 源几何、胶片物理画幅、胶片/相纸及完整引擎参数。
- 本次颗粒与眩光的已解析种子/随机实现身份，片边和日期内容的已解析值。
- 后期版本、曲线/色轮/HSL/混合等参数、输出几何。
- 输出尺寸、色域、位深、格式、编码质量、拍摄/GPS 保留选项。
- 目标文件授权与发布事务凭据。

云端流若不能 seek，按需保留原文件字节到受控临时文件，不转换为 JPEG。导出前后核对源版本，途中原片改变则拒绝发布。重新绑定 URI 不依赖文件名猜测内容。

## 5. 与现代 Windows `export_frame` 对齐的顺序

```text
冻结请求与源版本
  → 核对可复用会话/缓存
  → 必要时完整 RAW 解码、相机白平衡、镜头校正
  → 源几何与全局测光/场景置位
  → 原生尺寸胶片曝光、光晕、显影、颗粒
  → 相纸冲印与扫描
  → Post-Dev
  → 输出几何、所选输出尺寸
  → 目标色域与传递函数
  → 有界读回与编码
  → 校验、发布
```

源几何和成片输出几何必须分开。源几何可能影响测光、物理画幅和显影，不能简单移到编码前。选择小尺寸成片时，先缩小原片再显影也不能冒充全尺寸显影后缩小；预览可有自己的响应策略，但正式输出要有明确合同。

Windows 的工作空间、输出色域映射与 Post-Dev 顺序须按实际目标版本核对，不增加重复的高光压缩。旧编辑保留旧后期版本，新流程需要显式版本与兼容策略；不能全局换色彩处理后让历史项目变色。

## 6. 阶段缓存与随机效果

| 缓存 | 必须包含的身份 | 典型失效条件 |
| --- | --- | --- |
| 解码源 | 原片版本、解码器、WB、镜头与校准版本 | 换源、WB/镜头改变 |
| 负片 | 源身份、源几何、画幅、胶片、曝光与胶片效果、随机实现 | 胶片/曝光/颗粒/光晕改变 |
| 扫描成片 | 负片身份、相纸、配光、相纸效果、随机实现 | 相纸/配光改变 |
| 最终输出 | 成片身份、后期、输出几何、色彩与尺寸 | 后期/输出设置改变 |

粒子和眩光不能为了缓存而关闭。应冻结本次随机实现，并让预览、高分辨率重建、导出和失败重试明确使用同一实现身份。禁止把有随机效果的任意旧文件不加校验地当作缓存。

缓存采用租约、容量上限和逐阶段淘汰；优先复用仍有效的阶段。桌面式 suspend/resume 保存原始 float/U16 字节、维度、别名和必要状态，可用受控文件支持低驻留恢复，不用低质量图片代替。任何暂存都必须计入 IO、磁盘容量及取消清理；不能把 mmap 文件大小等同于实际驻留内存。

缓存逻辑必须按真实节点依赖验证。例如放大机曝光是否复用负片，要由实际节点合同决定，不能按控件名字分类。格式或 EXIF 开关改变通常可复用计算结果，但编码成品缓存需要独立包含这些选项。

## 7. 手机端有界资源执行

进程隔离不增加物理内存，也不会自动让 GPU 更快。必须另做执行器适配：

1. 支持时查询 Vulkan heap budget/usage，同时检查单缓冲区范围、分配限制和当前图面占用；不支持预算扩展时采用保守策略。预算是动态估计，不是成功保证。
2. 全局测光、最大值及其他归约先按完整逻辑得到一致统计，不能每块各算一套曝光。
3. 点运算分段，保留全局坐标与同一参数。颗粒使用完整图尺寸和全局采样位置，避免分块改变尺寸或随机纹理。
4. FIR 保留足够 halo、边界反射和 tap 累加顺序；仅输出中心有效区域。
5. IIR 保留双向递推的状态、方向和初始条件。不能把相邻块独立模糊后直接拼起来。
6. 控制单次 dispatch 工作量并保留合法同步。不能去掉必要 barrier/flush 换取看似更快的计时。
7. 原生编码按行/条带消费数据。TIFF 延续有界行写出；JPEG/PNG 需为原生行编码方案建立独立像素与元数据对照，不能默认当前整张 Bitmap 编码已流式化。
8. 释放最后读者已经结束的中间图面，统计 GPU 暂存、持久图、CPU 解码、读回、显示和编码的重叠峰值。

先针对实测瓶颈实现有界 CPU 并行：LibRaw OpenMP 运行库和 ABI 完整验证、嵌套并行控制、线程数上限；镜头校正按独立行并行，保持每像素 Newton 与双线性采样算术。逐位一致先通过，再评估实际手机冷启动、热态和持续操作表现。

## 8. 设备丢失、任务与发布

建议任务状态：

```text
QUEUED → PREPARING → RENDERING → ENCODING → PUBLISHING → SUCCEEDED
           └──────────────→ FAILED / CANCELLED
```

状态与完成凭据由协调器持久化，重计算仍串行；取消和进度旁路不能等待正忙的渲染队列。

- 捕获设备丢失后锁存失效状态，旧设备、队列、GPU 指针和会话禁止继续使用。
- 终止旧进度任务和计算所有权后再清退设备；新逻辑设备创建成功才建立新一代会话。
- worker 崩溃通过进程连接死亡回调标记任务失败，保留原片、编辑和界面状态；不承诺能够防止系统级驱动或整机故障。
- 不自动无限重试。若允许重试，沿用原始请求与随机身份，核对是否已经发布，避免重复文件。
- app 私有临时文件完整写入并校验后，经现有 `ExportPublisher` 发布。MediaStore 与 Windows 文件 rename 的 API 不同，但“成功后可见、失败无半成品”的结果合同一致。
- 发布途中进程死亡需要凭 `jobId`、目标 URI、pending 状态和完成凭据做恢复，不能仅凭文件名判断成功。
- 设备预算不足时排队、清理闲置缓存或明确失败；不能静默降低尺寸、效果或位深。

## 9. 建议开发顺序与每批门槛

| 批次 | 范围 | 必须通过后才进入下一批 |
| --- | --- | --- |
| E1 | 冻结完整请求、统一协调器、结构化错误、失效设备恢复；补真实阶段与内存诊断 | 参数不漂移；设备失效后无旧句柄复用；取消/错误不发布；当前编辑保留 |
| E2 | 有界 RAW 与镜头并行，补共享运行库、ABI 和许可证 | 旧 RAW/自定义 WB/镜头样本像素保持，完整输出保持；独立旧新交错计时和内存对照 |
| E3 | `:render` 独立 host 与统一所有者、异步 IPC、前台生命周期、进程死亡 | worker 退出不破坏项目；描述符无泄漏；没有重复整图 GPU 驻留；旧功能回归 |
| E4 | 随机身份、源/负片/成片缓存、精确 suspend/resume | 每阶段失效矩阵；颗粒/眩光不变；损坏/过期缓存拒绝；容量不足和取消安全 |
| E5 | 等价分段、IIR 状态、原生行编码、完整 Windows 输出顺序 | 带符号混合、边界、全局曝光、旋转裁剪、RGBA16 和编码像素独立对照；无图缝 |
| E6 | 完整应用集成、持续操作和真机 | 24MP/50MP、多次连续、后台/锁屏/取消/重启/满盘；小米17Pro/OPPO等实际设备，冷暖时延与峰值公开记录 |

E1 的错误恢复不能替代 E3 的崩溃隔离，E3 的进程隔离不能替代 E5 的降峰值。不得因某一批通过就把整个 F03/F16/F17 标为完成。

## 10. 可沿用的基础与仍缺内容

可沿用：`EditSnapshot`、`ExportOptions`、`EngineTaskQueue`、`Rgba16Source`、`RenderDiskCache` 租约、`ExportPublisher`、分阶段计时、已有 RAW/全尺寸/取消/项目回归，以及实际 PC 二进制同源像素对照工具。

仍需开发或重新验收：上述完整请求与故障状态机、独立 host、随机实现持久合同、阶段缓存、OpenMP/镜头并行、完整分段执行与行编码、全后期/工作空间对齐，以及真实手机设备丢失原因和连续大图稳定性。本方案没有声称这些已经实现。

核对依据：本地 Windows 正式版 commit `2ca735ad60a998e925bf346f57d80012bdb5c6bf` 的 `desktop/HOST-PROTOCOL.md`、`engine/host/main.cpp`、RAW 与镜头实现；Android 当前源码与 `.tmp/pc-export-diagnosis/diagnosis.json`。平台约束参考 Android Developers 的 Service、AIDL、ParcelFileDescriptor、TransactionTooLargeException、前台 mediaProcessing 文档，以及 Khronos Vulkan 的设备丢失与内存预算规范。
