# 观景台预览与导出外观一致性修复

日期：2026-11-15。版本保持 `0.1.6`、versionCode `7`。

## 问题与定位

反馈中的观景台与合成图片有相同布局，但第二排夜景导出后明显变亮、偏黄。目前只有截图，无法确认这些照片是已调色成片还是尚未显影的原片，不能把测试样本说成用户原片复现。

代码中确认了一条可复现的错误路径：

1. 观景台可以直接展示原片缩略图，包括已有历史编辑、但当前没有加载成片预览的照片。
2. 项目此前只记录来源 URI、编辑版本和预览缓存，没有明确记录当前显示的是原片还是成片；部分原片预览还会被记录在 `rendered_preview` 中。
3. 项目导出读取该 URI 保存的参数，只要有历史编辑就重新应用胶片、相纸和调色。因此，屏幕上的原片会在导出时获得本来不可见的处理。

该问题属于观景台的显示来源与导出来源语义不一致；这次修复没有修改胶片模型、相纸、调色公式或原生渲染代码。

## 修复内容

- `TableSource.appearance` 明确保存 `original` 或 `edited`；旧项目缺少该字段时保留 `null`。草稿、项目创建、保存、恢复和批量加入都传递该状态，未知枚举值拒绝读取。
- 新项目默认按保存的显示类型导出。原片从原文件按合成所需尺寸解码，不再自动套用该 URI 的历史参数；成片继续使用已保存的编辑版本与正式显影链路。
- 即使导出原片，仍冻结并验证实际存储的编辑参数，防止导出期间来源、版本或编辑变化后继续发布。跳过显影不代表删除或忽略编辑记录的并发保护。
- “使用最新编辑”继续作为显式选项，开启后按当前保存参数生成，包括当前显示为原片的照片；补充了说明文字。此时跳过没有必要的旧预览识别。
- 不使用观景台小预览作为导出像素。来源解码、PNG/JPEG 编码质量、项目长边选项、单张输出、RAW 输出及已有容量上限保持原规则。

主要代码：`LightTableProject.kt`、`GalleryScreen.kt`、`LightTableProjectsController.kt`、`TableExportSession.kt` 与 `TableOriginalAppearance.kt`。

## 旧项目兼容边界

旧项目没有显示类型，不能只根据是否存在历史编辑可靠推断。Android 9 及以上在导出旧项目时，以缓存中的可见预览与原片的有界 sRGB 解码进行保守匹配：解码尺寸不超过 640 像素，并使用均值误差和异常样本比例双重门槛。只在预览足够接近原片时按原片导出，不回写历史项目，也不以缓存代替原始文件。

该识别只在导出阶段的 IO 工作中执行；新项目及显式采用最新编辑时不需要额外兼容解码，不进入调参、胶片切换或画布滚动链路。

历史信息不足仍有边界：缓存已丢失、预览与原片的解码差异较大、Android 8.0/8.1、以及非常细微的编辑，无法保证推断覆盖所有情况。旧项目识别不是精确的编辑参数恢复。RAW 的相机原图预览也不被当作可以无损放大的显影来源，原有未显影 RAW 拒绝规则保持。

最终同一构建的 11 组、29 条记录全部通过，记录位于 `.tmp/libraw-upgrade/table-release/`。测试后拉回实际安装宿主，与安装源 APK 摘要相同；宿主内六份原生库与正式包相同，401 项正式与测试输入文件在测试后重新校验保持。真实 Z6II RAW 项目输出与独立单图系统栅格参考整图逐通道最大误差为 0。

新增 `TableAppearanceAudit` 覆盖九张混合和重复摆放的照片：在原片已有强亮度、暖色参数的前提下，默认导出仍保持各原片摆放区域中心采样的精确像素；成片保留显影参数，显式最新编辑会改变原片；192 像素与 640 像素旧原片缓存可识别，明显改变的旧成片缓存不能误判为原片。显示类型经过 JSON 和项目关闭重开保持，导出前后存储的编辑 JSON 字节、参数快照和保存项目保持，临时文件清理完成。

最初的“编辑参数变化”断言失败也保留了诊断：测试在胶片目录加载前建立基准，启动后 `overscan_edge_text` 从内部 ID `KODAK_PORTRA_400` 解析为正式文字 `KODAK PORTRA 400`。已将目录初始化放到基准采集之前，仍严格比较全部参数及实际存储字节，没有删除或放宽编辑保护断言。原失败记录在 `.tmp/table-appearance/diagnostic-run.log`。

相关回归包括合成几何与透明度、透明原片、真实 Z6II RAW 虚拟版本输出、项目存储与实际界面恢复、工作台恢复、导出缓存、调参中断恢复、胶片相纸 U16 像素参考及 Z5II HE★ 导入和全尺寸输出。运行环境为 API 37 x86_64 模拟器；ARM64 完成编译，不能等同于 ARM 真机测试。
